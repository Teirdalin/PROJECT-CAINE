# PROJECT CAINE technical audit and improvements

October 9, 2026 — **0.3.15-framework-dev**, Windows x86, JDL-1.

This pass implements reliability, menu and graphics improvements against the
installed Bloodlines integration. It does not claim a complete engine port,
resolution of every original game bug, or full live gameplay acceptance. CAINE
remains a framework; Bloodlines: Unscripted remains a separate optional mod.

## Reliability fixes

- **Hook batches:** serialize MinHook queue ownership between CAINE components
  and plugins. Check the module's disk fingerprint once per batch and validate
  each live target. Reject reused trampoline-output pointers. Roll back every
  staged hook when creation or queuing fails, so a later unrelated queue apply
  cannot enable an abandoned hook. If activation might have occurred, disable
  hooks while retaining trampolines until safe teardown.
- **Native bridge initialization:** dialogue detours pass through until the
  complete bridge is ready. Failure of the second module's hook batch disables
  the first batch without freeing potentially executing trampolines. This
  reduces exposure to partially initialized dialogue handling.
- **Startup callback lifetime:** late-module discovery keeps the callback logger
  immutable after publication, avoiding a worker/playback-thread data race.
  Failed filename recognition delegates to the installed video routine.
- **Plugin callback failures:** a failed game-UI callback releases native
  dialogue ownership and disables that UI until restart. Its control work and
  hooks remain resident. A failed control callback also releases ownership.
  Failed plugins cannot reclaim dialogue through the host API. Repeated frames
  no longer reenter the same failed UI callback or flood its diagnostic.
- **Input isolation:** the six native mouse/camera hooks capture only the
  verified main CInput instance. Other instances call their original routines.
  Rendering callbacks verify the game-window thread; focus, native pause and
  an expired frame lease retain the existing input-release paths.
- **Native-menu fallback:** choosing native menus no longer disables plugin
  gameplay overlays or causes the initialized modern menu to swallow native
  settings. Native row limits remain enforced when modern menus are off.
- **Save/load boundaries:** recognize native JSAV headers and revalidate the
  selected save in the active game profile when the action is submitted.
  Missing, redirected or unrecognized loads are rejected. A save created after
  the browser opened now triggers overwrite confirmation, including empty and
  differently cased filenames. Saving requires an active game. The engine still
  performs serialization; CAINE does not rewrite native saves.
- **Launcher scope:** another installation running Bloodlines no longer blocks
  the launcher for the selected installation.

The audited paths include startup, hook lifetime, mod discovery and callbacks,
native dialogue/Python integration, owned serialization, input, menu transitions,
logging/crash reporting, updates and deployment. Existing private Unscripted
service/persistence/voice tests were rerun. This release contains no AI service,
credentials, game binaries or unofficial SDK implementation code.

## Menus and configuration

Settings now have Audio, Mouse, Keyboard, Gameplay, Display, Graphics and
Framework pages. Resolution remains the native display-mode dropdown. Graphics
consolidates the game's texture, lighting, bump mapping, shadow, geometry, gamma,
brightness, particle and effect controls, with descriptions and native values.

The new Framework page edits actual CAINE.ini preferences: modern menus, startup
logo skipping, intro skipping/hold duration, update checking/development releases/
interval, crash reporting/dumps/report limits, detailed logging and interface
scale. Scale (75–150%) and logging apply immediately. Other controls explicitly
require restart. Writes preserve unrelated configuration, bound numeric input
and reject redirected paths. Shared active-profile resolution replaces duplicate
menu/intro parsing.

Main-menu Load proceeds directly; in-game Load retains the unsaved-progress
confirmation. Continue still selects the newest recognizable save and honors
mod readiness. Update Available opens a review/confirmation dialog; downloading
begins only after Install and Restart. Merely opening the update panel no longer
initiates installation.

Keyboard binding discovery is cached briefly while browsing, refreshed on
entry, and revalidated when editing. Primary/alternative boxes and the key-capture
popup remain. The inert `in_mlook` setting was removed: native mouselook is an
input-button state, not a registered variable. Checkbox descriptions wrap and
remain clickable while respecting disabled controls. The rendered input fixture
checks both cases. Small-screen
small-screen conversation panels reserve enough space for the pinned composer
and navigation footer.

Main/pause navigation, settings, load/save, Mods/configuration, credits, update
and confirmation routes were reviewed. The CAINE logo, gothic colors, compact
quit panel and left navigation are retained. Character creation, character
sheet, inventory, quests, computers and other specialized native panels retain
their game behavior and artwork. This is deliberate compatibility coverage;
these screens have not all been replaced or exercised in live gameplay.

## Graphics and performance

Two functional native controls were added: **trilinear filtering**
(`mat_trilinear`) and a **30–240 FPS cap** (`fps_max`). Both were verified as
registered variables with engine consumers in the installed build. Since these
variables are not archived by the engine, explicitly saved preferences are
stored per active game profile in CAINE.ini and restored through the verified
command backend. An absent preference leaves the game's current value alone.
The existing 60–135 FOV control uses the native `fov` command immediately and
retains its load/restart persistence. A 60 FPS cap is the conservative guidance
for legacy timing; higher settings still need gameplay acceptance.

Graphics displays the actual D3D9 presentation mode, multisampling and hardware
limits. The live smoke test reported 1280×720 windowed, MSAA 0, anisotropy limit
16 and pixel-shader hardware support 3.0. The latter two are device capabilities,
not proof that anisotropic filtering or modern shaders are enabled in Bloodlines.

The font atlas previously used a default-pool texture released with every
visible frame. A small, documented Dear ImGui backend extension now retains a
static managed-pool atlas, with the old allocation path as a fallback. Geometry
and fallback default-pool resources are still released before native Reset can
occur. Eight rendered frames and a real D3D9 Reset require one font upload in
the regression; the actual game also reported one upload across many frames.
Managed resources and Reset requirements follow
[Microsoft's D3DPOOL documentation](https://learn.microsoft.com/en-us/windows/win32/direct3d9/d3dpool).

Native variable lookups are cached without caching their changing values.
Binding scans no longer read all 256 keys every frame. Gameplay-UI ownership is
polled once after pending actions and input processing. Renderer diagnostics are
bounded and logged only on change. These remove repeated work; no gameplay FPS
benchmark or quantified overall speedup is claimed.

## Engine feasibility and patch compatibility

The inspected installation uses a Bloodlines-specific early Source x86 engine
and Direct3D 9. Verified interfaces include VEngineClient006, VEngineCvar001
and VENGINE_GAMEUIFUNCS_VERSION001. No precise Valve source changelist was
established from the installed binaries.

Valve's current public [Source SDK 2013](https://github.com/ValveSoftware/source-sdk-2013)
provides game code for other Source games and requires the SDK 2013 runtime.
Combined with the observed Bloodlines interfaces and native layouts, this means
a drop-in engine upgrade is not a supported route. That conclusion is an
engineering inference, not a completed compatibility port. No proprietary
engine components are redistributed.

- **Lighting/shadows/reflections:** existing native quality settings work within
  the original pipeline. Modern HDR/PBR materials, cascaded shadows, volumetrics
  and screen-space reflections require additional renderer/material/map work;
  none was backported or presented as an enabled setting.
- **Anti-aliasing:** the observed render target is not multisampled. MSAA needs
  compatible creation/reset parameters, render/depth targets and capability
  checks, as described in [Microsoft's D3D9 antialiasing documentation](https://learn.microsoft.com/en-us/windows/win32/direct3d9/full-scene-antialiasing).
  A render-state toggle or invented CVar cannot supply that pipeline.
- **Filtering:** trilinear filtering is exposed. `mat_forceaniso` was not found
  as a registered variable in the inspected modules. Hardware AF support alone
  is insufficient to offer a working AF control; sampler interception remains
  future work.
- **Resolution/widescreen/draw distance:** native resolution, FOV and CAINE UI
  scale are exposed. Existing widescreen fixes are preserved. Render scaling
  needs a real offscreen/upscaling path; BSP visibility and geometry limits
  cannot safely be replaced by an arbitrary distance slider.
- **Textures:** authored higher-resolution content is feasible through separate
  mods, subject to memory/material compatibility. No unlicensed texture pack
  was added or existing content silently replaced.
- **External renderers:** [ReShade](https://reshade.me/) supports D3D9 postprocessing;
  depth-dependent effects still need Bloodlines-specific testing. [DXVK](https://github.com/doitsujin/dxvk)
  translates D3D9 to Vulkan, but its maintainers describe [Windows support limitations](https://github.com/doitsujin/dxvk/wiki/Windows).
  Neither supplies newer Source game/lighting code. Neither was installed or
  enabled, and the disabled Remix integration was preserved.

Installed Unofficial Patch documentation identifies version 11.5. Existing
loader bug/widescreen settings already cover several memory, LOD, light and
display fixes, so this pass preserves those modules and configuration.

Real startup inspection found the installed widescreen module relocates video
playback. The earlier startup-caller hook installed but did not skip this route.
A second hook now recognizes the exact reviewed module hash/RVA/prologue and
skips only the four startup logos. It accepts the active game's media paths and
delegates story/unrelated videos with their original arguments and return value.
The production detour passes mapped installed-binary regressions. Unknown patch
builds remain untouched; final live startup acceptance is still pending.

## Validation and remaining work

**47 CTest checks pass**, including real x86 detours against mapped installed
modules, hook rollback, native input/dialogue/Python/intro paths, long strings,
owned serialization, logging/crash behavior, save/binding/preferences logic,
mod ABI failure paths and D3D9 rendering/reset. **69 private Python tests pass**.
An exported public framework-only tree builds without Unscripted or game files
and passes **37 checks**.
Installer/updater labs cover ownership, tamper rejection, rollback, ZIP traversal,
exact-process waiting, preserved saves/config/mods and restart arguments.

An earlier 0.3.15 payload was installed into the protected game copy; SHA-256
verification confirmed **2,073 protected files unchanged**, including the normal
installation, saves, settings and Unscripted. A real game launch bound all 22
native settings, loaded the optional mod, and rendered CAINE's main menu without
rendering errors. No save, map, character or online AI request was initiated.

The automated startup console command did not execute, so automated quit was
not accepted. That test game was left running for the user to close; loaded
libraries were not replaced or the process forcibly terminated. Final startup
coexistence and plugin-failure changes are staged for deployment after closure.
This smoke proves native initialization/main-menu rendering, not every menu
action or gameplay transition. Native configuration snapshots were retained
to restore any test-exit changes after the process closes.

An existing 0.3.13 native fatal-crash log was also reviewed. It records an invalid
write in vstdlib.dll+0x4f59 after returning to the menu. That location alone does
not establish the cause or show that the historical character-creation crash
has been fixed. First-chance CAINE reports remain explicitly distinguished from
fatal crashes. No speculative patch to the game allocator was applied.

Manual acceptance still required:

1. Fresh boot: four logos skipped, story/intro preserved, normal launcher works.
2. New character → cinematic/tutorial → level transition, then repeated return
   to menu and exit; collect a fresh report if the crash recurs.
3. Continue/load/save/overwrite across active game profiles, including real
   world transitions and save compatibility.
4. Pause/resume/native specialized panels, alt-tab, cursor/camera restoration,
   resolution/fullscreen Reset and minimum-screen/max-scale navigation.
5. All settings Apply/Discard, primary/alternative rebinds and persisted values
   in live play; visual effect and timing acceptance of native graphics controls.
6. Unscripted NPC interaction, speech, service/network failure and save-specific
   memory, plus native-menu mode and other community patch fingerprints.
7. Interactive update confirmation/progress and restart from normal launchers.

Experimental renderer reconstruction remains disabled/unimplemented. Future
work should add separately validated native profiles and renderer capabilities
before exposing additional controls, while retaining native saves and patch
ownership boundaries.
